# Slack 對話

## 怎麼搜

Slack 的 MCP 工具各不相同。先看環境裡是哪個 Slack MCP，並看它的工具 schema。可能要先 `mcp_auth`。認證失敗就停，把這個缺口報出來。

1. **按作者收窄。** 搜 PR 作者在 PR 合併日前後的訊息。範圍會小很多，也常常能挖到關鍵內容。
3. **搜 PR URL。** 評審或討論時，Slack 裡經常會帶上 PR 連結。搜這條 PR 的 URL（或者只搜 `/pull/<number>`）。
4. **搜錯誤字串。** 如果程式碼在處理某個具體錯誤，就搜這個錯誤字串。事故討論串經常會冒出來。

## 常見陷阱

- **頻道歷史有限。** 很老的訊息可能因為保留策略已經不在了。如果某個日期之前什麼都搜不到，把這個保留期斷點寫明。
- **私信搜不到。** 很多決定發生在搜不到的私信裡。你會漏掉。這是已知限制。
- **把隨口一句當成「決定」。** Slack 很隨便。"Lol just do the thing"（哈哈，幹就完了）不是決定，哪怕它出現在提交之前。要找經過考慮的討論。
- **單條訊息會失去上下文。** 不看整串的話，單條訊息經常會被讀歪。始終把討論串拉全。
- **認證失敗。** MCP 沒認證就停。不要編造發現。報告 Slack 搜不了。
